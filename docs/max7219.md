# MAX7219 matrix chains

`configure_led_displays` accepts controller 3 in its existing eight-byte record:
`id, 3, layout, SCLK, DIN, LOAD, modules, 0`. Layouts 5/6/7/8 select FC16/Generic/Parola/ICStation physical wiring. Modules must be 1–64; the combined HT16K33/TM1637/MAX7219 limit is sixteen displays. Output uses the existing RGB565 project display IDs 128–143, width `8*modules`, height 8. Configuration rejects duplicate IDs, shared chip selects, and conflicting TM1637 lines. It preserves other circuit devices.

GPIO rising clock edges shift DIN regardless of LOAD. LOAD rising latches each chip's last sixteen bits; the nearest chip receives the latest word. Hardware SPI feeds the same shift state even when another chip select is active. A mismatched clock does not shift; a matching clock with different MOSI samples the last observed DIN level. GPIO bit-banging and hardware SPI use the same registers.

Digit RAM, code-B decode, scan limit, intensity, shutdown, and display test follow the [datasheet](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX7219-MAX7221.pdf). Display test overrides RAM, scan, shutdown and intensity. RGB red intensity reflects nominal `(2*n+1)/32` duty, rounded to five-bit color. It is not an analog brightness calibration. MAX7221's distinct CS gating is not modeled by this configuration.

Physical layout follows [MD_MAX72XX](https://github.com/MajicDesigns/MD_MAX72XX/tree/b852c70328f30a11ca2bd36149f18379feaddea2/src), with column zero on the right and chained modules extending left. No default layout is inferred from firmware or a bare controller name. Firmware reboot retains the external controller; actual driver initialization subsequently rewrites its registers.

Native tests cover latch edges, clocks while unselected, daisy-chain order, held DIN/wrong clock, decode, scan limit, display-test override and bounded allocation. The companion application's unchanged-driver fixture covers all four layouts on S3/C3/C6, hardware SPI and GPIO bit-banging, multiple chip selects, control commands, firmware reboot, and production-browser lifecycle.
